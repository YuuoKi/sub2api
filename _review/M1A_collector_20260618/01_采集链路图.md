# 01 · 采集链路图 —— 一次 LLM 生产从请求到落库

> 证据目录：`backend/internal/handler/gateway_handler.go`、`backend/internal/service/gateway_service.go` 等（行号见 [02](./02_燃料可达性结论.md)）

## 现状链路（计费视角，prompt/response 中途丢弃）

```
客户端请求
   │  body(原始JSON=prompt) 到达 handler
   ▼
[handler] ParseGatewayRequest → parsedReq (*ParsedRequest)         ★可抓点1: parsedReq.Body = prompt(全量在手)
   │        gateway_request.go:65  (Body/System/Messages 都在)
   ▼
[handler] Forward 转发到上游 AI(Anthropic/OpenAI/…)
   │
   ├─ 流式: 上游响应 边收边转发给客户端                              ✗ response 不缓冲(只解析token计数)
   │        各 emit 出口 = 客户端可见字节                            ★可抓点2: 限容 tee 抓 response(乙,需新建)
   │
   └─ 非流式: 读上游 body → 转换 → c.Data 写客户端                   ★可抓点2': body 在 c.Data 前可抓
   ▼
[handler] result (*ForwardResult)  —— 只含 Usage(token)/Model/timing  ✗ 无 response 正文字段 (gateway_service.go:490)
   ▼
[handler] submitUsageRecordTask(闭包)  —— 有界 worker 池, 异步旁路     ★可抓点3: 闭包内同时握有 parsedReq + result
   │        gateway_handler.go:507   (天然满足判断基准4: 异步/不阻塞主路由)
   ▼
[service] RecordUsage(input{ Result, ParsedRequest, ... })           parsedReq 还在!  gateway_handler.go:511
   │
   ▼  ✗ 断点: ParsedRequest 在此被丢弃 (recordUsageCoreInput 不接它)   gateway_service.go:8284
[service] recordUsageCore → buildRecordUsageLog → writeUsageLogBestEffort
   │                         gateway_service.go:8428 / 8471
   ▼
[repo] INSERT usage_logs (只有 token/成本/元数据, 无 prompt/response)  usage_log_repo.go:309
```

## 三个可抓点小结
| 可抓点 | 抓什么 | 现状 | 改造 |
|---|---|---|---|
| ★1 handler `parsedReq.Body` | prompt（输入，全量） | 已在手，向下传到 RecordUsage | **甲**：只是没继续往采集写 |
| ★2 Forward 各 emit 出口 | response（产出） | **未留存**，边转发边丢 | **乙**：需新建限容 tee 把客户端可见字节抓回 `ForwardResult` |
| ★3 `submitUsageRecordTask` 闭包 | prompt + response + 归因 | 已是异步旁路 | **采集落库的最佳挂载点**（与计费隔离、fail-open） |

## 目标链路（M1 改造后，新增旁路，不动主调用）
```
… Forward(各 emit 出口) ──限容tee(fail-open)──► result.ResponseSample(≤64KiB)
                                                         │
submitUsageRecordTask 闭包:                              ▼
   RecordUsage(...)   ← 计费(不变)                  contentCollector.Collect(
   ───────────────── 隔离 ─────────────────            prompt=parsedReq.Body,
   contentCollector.Collect(...)  ← 新增采集            response=result.ResponseSample, 归因…)
        │  入库前脱敏(prompt+response)                    │ 自吞错误+池recover兜底 → 绝不影响主调用/计费
        ▼
   INSERT ai_generation_content (脱敏prompt/response + 归因 + 预留 task_id/质量列)   ← 新独立表
```
> 设计要点：采集是 RecordUsage 的**兄弟调用**（不嵌进计费、不进 recordUsageCore 分支），collector 失败/panic 被 worker 池 `recover`（gateway_handler.go:1844）兜底。详见 [03](./03_设计方案_字段存法脱敏架构.md) / [04](./04_改动清单_风险_回滚_验证.md)。
