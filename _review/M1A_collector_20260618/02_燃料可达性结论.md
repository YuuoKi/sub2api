# 02 · 燃料可达性结论（§6 战略分叉）

> 判定：**prompt = 情况甲（够得到）/ response = 情况乙（够不到）** 的混合。
> 全部 file:line 基于 `wujie/trunk`（HEAD 40e83bf4）实读 + 独立子代理交叉验证。

## 采集口写入点（确认）
- `recordUsageCore` 组装 `UsageLog` → `buildRecordUsageLog`（`backend/internal/service/gateway_service.go:8428`）→ `writeUsageLogBestEffort`（`gateway_service.go:8471`）→ `usageLogRepo.Create` → `createSingle` INSERT（`backend/internal/repository/usage_log_repo.go:246/309`）。
- 写入时 `UsageLog` 结构体**只有** token/成本/各类 model 名/归因 id/ip/ua/timing/image 计数——**无 prompt、无 response**（schema 见 `backend/ent/schema/usage_log.go`，`grep prompt|result|content|response` 零命中）。

## PROMPT（输入）＝情况甲 ✅ 够得到
| 证据 | file:line |
|---|---|
| `ParsedRequest` 持有原始请求体 `Body []byte`（+解析好的 `System`/`Messages`/`Model`/`Stream`） | `backend/internal/service/gateway_request.go:65-84` |
| handler 把 `parsedReq` 传进 `RecordUsage`（`ParsedRequest: parsedReq`） | `backend/internal/handler/gateway_handler.go:511` |
| 但 `RecordUsage` 调 `recordUsageCore` 时**丢弃** ParsedRequest（`recordUsageCoreInput` 无此字段） | `gateway_service.go:8284`（input 定义 `:8346-8360`） |
| 使用量记录**本就异步旁路**（有界 worker 池，避免热路径无界 goroutine） | `gateway_handler.go:507-534`（池 recover `:1844`） |

**结论**：prompt 全量就在异步旁路闭包手上，只是没继续写到采集——**往下多传一层即可**，且不碰主路由（判断基准4 天然满足）。改动属"加字段/接线"级。

## RESPONSE（产出）＝情况乙 ⚠️ 够不到
| 证据 | file:line |
|---|---|
| `ForwardResult` 只含 `Usage`(token)/`Model`/`Duration`/`ImageCount`…，**无响应正文字段** | `gateway_service.go:490-506` |
| 成功响应**边收边转发给客户端、不缓冲**；流式仅用状态机抽 token 计数 | 各 emit 出口（下表） |
| 全文 response 系统内**唯一**留存只在错误路径 `UpstreamFailoverError.ResponseBody` | `gateway_service.go:511` |

**response 的 6 个 emit 出口（客户端可见字节处，未来限容 tee 的插入点）：**
| # | 路径 / 函数 | 出口 file:line |
|---|---|---|
| 1 | 原生 Anthropic 流式 `handleStreamingResponse` | `gateway_service.go:7147` / 写出 `:7475-7495` |
| 2 | 原生 Anthropic 非流式 `handleNonStreamingResponse` | `:7769` / `body`@`:7833` |
| 3 | Anthropic 透传流式 | `:5266` / `:5414-5426` |
| 4 | Anthropic 透传非流式 | `:5564` / `:5586` |
| 5 | CC 转换流式 `handleCCStreamingFromAnthropic` | `gateway_forward_as_chat_completions.go:343` / `writeChunk`@`:401` |
| 6 | CC 转换非流式 `handleCCBufferedFromAnthropic` | `:217` / `:324` |

**结论**：response 全文未留存，要采集必须在中继**热路径**加"限容 tee"把客户端可见字节抓回 `ForwardResult`——这是动架构、触判断基准4 红线的部分（学者已定：限容 64KiB + fail-open）。

## 一句话给学者
> 采集口能不能承载"全量生产数据采集"？**能，但要分两半打**：prompt 半个是顺手（甲）；response 半个要在热路径加限容旁路（乙，已用"限容+失败即弃"守住主路由）。所以 M1 是"加字段(prompt) + 加限容 tee(response) + 新独立内容表"的组合，不是单纯加字段。
