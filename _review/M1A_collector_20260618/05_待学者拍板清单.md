# 05 · 待学者拍板清单（M1-B 施工前定）

> 大方向你已拍板两条（见 [00](./00_START_HERE.md)）：response=捕获但限容+fail-open；存储=新建独立内容表。
> 以下是 M1-B 前还需你点头的细节，每条给**选项 + 推荐**。

| # | 决策点 | 选项 | 推荐 |
|---|---|---|---|
| 1 | **response 限容阈值** | 32K / **64KiB** / 128K | **64KiB**（覆盖绝大多数文本补全；超大截断置 `truncated`） |
| 1b | **prompt 是否也限容** | 不限 / 限容（如 256K） | **限容**（防超长 prompt 撑大表；阈值可宽于 response） |
| 2 | **内容表保留期** | 与计费同 / **独立较短** / 永久 | **独立较短 + 清理任务**（内容/PII 不宜久留，独立于计费保留期） |
| 3 | **M1 首切范围** | 仅 LLM 中继(Messages+Chat Completions) / 同时含视频·drama 产出 | **仅 LLM 先行**（视频/drama 走另一套 event 模型，另议；先把主流量燃料打通） |
| 4 | **PII 脱敏深度（M1）** | 仅 email+电话最小集 / 含证件·银行卡等 | **最小集起步**（`redaction_version` 可后续加，过度脱敏可接受） |
| 5 | **feature flag 生产默认** | **默认 false 灰度开** / 默认 on | **默认 false**（先灰度验证内存/延迟与脱敏效果，再放量） |
| 6 | **是否存 response 全文超大走对象存储** | M1 不做(截断) / M1 就做(选项C) | **M1 不做**（先 DB 直存+截断；对象存储作后续可选，避免 M1 多搭依赖） |
| 7 | **质量信号/采用动作回流** | M1 仅预留列 / M1 就接 QCanvas 回流 | **M1 仅预留**（`task_id`+`adoption_status`+`quality_score`）；**QCanvas 是独立仓、本次未侦察，回流是后续跨仓里程碑** |

## 一次拍完即可进 M1-B
以上 7 点 + 已定的两条大方向，构成 M1-B 全部设计输入。M1-B 照 [03](./03_设计方案_字段存法脱敏架构.md)/[04](./04_改动清单_风险_回滚_验证.md) 即可直接施工，不需再做设计判断。

## 守主线提醒
采集口是护城河第一锹，地位高于一切 UI/新功能。M1 范围严格限定"采集"：不优化 UI、不加无关功能、不碰主路由功能本身。**M1-A 出草案（本包）→ 你拍板 → M1-B 加字段+限容tee+新表施工（授权后另写）。**
