# 无界 Sub2API 老板本机运维 SOP

本独立 SOP 只用于本机受控环境的 `wujie-sub2api:local`。唯一入口是 `http://127.0.0.1:8080`，状态最高只能按实际证据标记为“待复核”或“可演示”。所有步骤都必须遵守：不得触碰生产，不得删除备份，不得发起真实调用，不得读取、复制、打印或提交 `.env`、密钥、token、cookie、员工 API Key 与数据库连接串。

## 1. 启动、状态与停止

从仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\wujie-local-entry.ps1 Start
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\wujie-local-entry.ps1 Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\wujie-local-entry.ps1 Stop
```

- `Start` 只使用已经存在的 `wujie-sub2api:local`，不自动构建、不切换其他镜像。
- `Status` 只读验证容器 `wujie-single-entry-sub2api`、精确镜像、`127.0.0.1:8080`、HTTP 200、无界 title 和 `:3000` 无监听。
- `Stop` 只停止 canonical 应用服务，保留数据库、Redis、volume 和备份。
- 任一检查失败即视为失败；禁止改用 `:3000`、官方镜像、旧容器或 mock 页面冒充成功。

禁止执行 `docker compose down -v`、展开 compose 配置或用容器 inspect 打印环境变量。

## 2. 员工额度模板

开员工或调整额度前，由老板或明确授权的管理员填写并留存以下审批记录。空项不得以默认值补齐。

| 字段 | 示例口径 | 验收要求 |
| --- | --- | --- |
| 员工与团队 | 员工姓名 / 分组 | 必须与实际登录身份一致 |
| 允许模型 | 明确模型 allowlist | 未列出的模型不可用 |
| 单任务上限 | USD/CNY 明确金额 | 超限必须显式拒绝 |
| 日/月额度 | USD/CNY 明确金额 | 不能用“无限”或空值兜底 |
| 并发上限 | 明确整数 | 与团队产能匹配 |
| 有效期 | 起止时间 | 过期后需要重新审批 |
| 审批人 | 老板或授权管理员 | 记录审批时间，不记录秘密 |

保存后只核对员工、分组、模型、额度、有效期和审批人；不得通过真实供应商调用验证额度。

## 3. 密钥轮换人工 Gate

密钥轮换必须由人在场操作，自动化不得代填、读取或回显秘密。

1. 确认轮换对象、影响供应商、员工分组、维护窗口和回滚责任人。
2. 在后台遮罩输入框中写入新密钥；聊天、终端、截图和审查包都不得出现明文。
3. 保存后只验证页面显示“已配置/脱敏”，不得点击任何会触发真实生成的测试动作。
4. 确认旧密钥已在供应商侧撤销，并在审计记录中只写轮换时间、操作者和密钥指纹末尾，不写完整值。
5. 如后台无法证明脱敏保存，立即停止并标记“已阻塞”；禁止恢复成历史明文或自动切换备用供应商。

## 4. 失败任务定位

按单个任务逐层定位，不凭猜测改配置：

1. 记录请求人、员工分组、本地 task ID、上游 task ID、模型、请求时间和当前终态。
2. 对照任务详情中的结构化错误、重试次数、资产 URL、usage 与授权消费状态；没有上游 ID 就不得写“供应商已执行”。
3. 核对 worker 是否领取任务、provider grant 是否消费、全局门是否开启、reserve/settle/release 是否形成闭环。
4. 资产 URL 缺失、终态不一致或错误原因不清时，保留原记录并标记“待复核/已阻塞”；禁止补假 URL、静默重试或改成 mock 成功。
5. 日志与截图只保留 task ID、状态、时间、脱敏错误和费用字段，不得包含 prompt 正文、密钥、cookie 或员工 API Key。

## 5. 费用异常核对

费用异常必须同时对齐事实与账本：

1. 比较请求规格、上游回传规格与计费规格，特别记录 1K/2K、时长、分辨率和模型差异。
2. 核对 tokens、供应商原始费用、汇率、平台费用、员工余额前后值与授权剩余次数。
3. 检查 reserve、settle、release 是否一一对应；失败任务不得同时保留成功结算和释放两种互斥结果。
4. 若账本差分无法解释，冻结相关员工或 provider 的新任务授权，保留原始记录并升级人工复核。
5. 不通过再次真实调用复现费用；只使用既有任务、账本和脱敏供应商回执。

## 6. 安全回滚

1. 先运行 `Status` 保存安全字段：容器名、镜像名、loopback 入口、HTTP 状态与 title 结论。
2. 运行 `Stop` 停止 canonical 应用；不要停止或删除数据库、Redis、volume 和备份。
3. 保留失败镜像及其 digest 供复盘，不执行 `docker image prune`、`docker system prune` 或任何批量清理。
4. 仅在负责人确认上一版镜像来源与 digest 后，人工恢复 `wujie-sub2api:local` 标签，再运行 `Start`。
5. 回滚后重新运行 `Status`。若任一检查失败，保持停止并标记“已阻塞”，禁止切换旧入口或对外暴露端口。

## 7. 隔离 DEV 恢复演练

恢复演练只允许写入全新隔离 DEV 目标，不得触碰生产数据库或当前 canonical 数据卷。

1. 选择已有备份副本，记录只读路径、文件大小、生成时间和 SHA-256；不得移动、改名或删除原备份。
2. 创建全新的隔离目录、Docker project 名、网络、数据库 volume 与数据库名；端口不得占用 canonical `:8080`，也不得绑定公网地址。
3. 将备份复制到隔离临时目录后恢复；恢复命令的目标必须再次人工核对为隔离数据库，禁止使用生产连接串。
4. 恢复后比较关键表数量：员工、分组、API Key 元数据、任务、usage、账本和资产索引。只比对计数与脱敏标识，不输出秘密字段。
5. 在隔离环境执行只读登录与历史查询；不得发起图片、视频或任何真实供应商调用。
6. 记录备份 hash、隔离目标、恢复命令、计数差分、失败原因和回滚责任人。任一差分不明即判定演练失败。
7. 演练结束只停止隔离容器；隔离数据的后续删除必须另行获得明确授权。本 SOP 不授权删除任何备份、volume 或数据库。

## 8. 每次操作的最小交接记录

- 操作人、时间、动作：`Start` / `Status` / `Stop` / 人工 Gate。
- canonical 镜像与容器、HTTP 200、无界 title、`:3000` 无监听结论。
- 员工/任务/账本只记录脱敏 ID 与状态。
- 未完成项、风险、显式失败原因和下一位责任人。
- 明确写明：未触生产、未删备份、未真实调用、未输出秘密。
