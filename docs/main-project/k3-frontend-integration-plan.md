# K3 前端融入主项目（北极星 V5）方案

日期：2026-07-17
分支：`codex/k3-apple-ui-experiment-20260717`（HEAD=`0a57e13c`）
作者：WP-C 融入方案架构师（本文档为纯方案，不含任何代码改动）

## 1. 一句话结论

**Sub2API 前端就是"无界 AI 管理中台"本体，融入 = 换骨，不是嵌入。**

不使用 iframe，不使用微前端，不存在"把 K3 塞进主项目"的说法——K3 打磨的这个前端**本身就是主项目的管理中台**。它与 QCanvas（无界智能画布）是两个并列的前端，各自独立部署、独立演进，只靠 **API 契约文档**（`docs/api/video-gateway-contract.md` 等）对齐，正如北极星 V5 总规划 Target C4 图所写："双仓只通过契约文档对齐；一个执行任务不得同时写两个仓"。

所以"融入"的真正含义是三件事：

1. **视觉层统一**：K3 的 `--ui-*` 设计变量与主项目"深色青绿"方向合并成一套（§3）。
2. **菜单换骨**：从"技术后台菜单"换成北极星 `#console` 章定义的业务菜单（总览 / 密钥库 / 成员与开卡 / 任务记录 / 系统折叠），菜单名全部说人话（§4）。
3. **契约保持不动**：后端、路由、权限、计费语义一行不动，只动表现层（§5、§7）。

### 2.2 当前菜单 IA 与北极星 `#console` 目标 IA 的差距

北极星 V5 `#console` 章定义的目标菜单只有六块：**总览、密钥库、成员与开卡、任务记录、系统（折叠组）**——按"老板看账、管理者开卡、员工跑任务、技术收进折叠"的业务逻辑组织。

| 目标导航（给谁用） | 现有对应 | 差距 |
|---|---|---|
| **总览**（老板） | `仪表盘 /admin/dashboard`，K3 已做 outcome-first | 控制台 v2 的动画数字卡、模型分布环形图、成员消费排行、**通道异常红条告警**尚未在本分支落地（wujie 分支 `BossOverviewView` 已实现，可参照） |
| **密钥库**（老板） | 无。密钥相关入口散落三处：`账号 /admin/accounts`（AI 账号池）、`渠道管理`（技术配置）、视频区`生成通道` | 缺一个统一的"密钥库"视图：通用 AI 账号 + 视频供应商双标签、密钥脱敏、连通性测试（wujie 分支 `KeyVaultView` 已实现，可参照） |
| **成员与开卡**（管理者） | `用户 /admin/users` + `分组 /admin/groups` | 缺"员工/工具双类型 + 一键开卡（额度+有效期）+ 完整 Key 只显示一次可复制 + 每人花费列"的开卡业务流（wujie 分支 `StaffView` 已实现，可参照） |
| **任务记录**（管理者/老板） | `视频生产 → 任务记录` + `用量 /admin/usage` | AI 调用记录路由存在但侧栏无直链（wujie 分支为 `/admin/console/ai-records`，由任务页内链跳转）；提示词采集标签未暴露 |
| **系统（折叠组）**（技术） | 已有折叠组 `系统`（生成通道、系统检查） | 试跑任务目前在"视频生产"组内而非系统组；`代理`、`设置`、`运维` 等技术项未纳入折叠，平铺在菜单里碍眼 |
| **（目标态不存在）** | 2C 遗留菜单：订阅、兑换码、优惠码、分销管理、订单管理 | 北极星定性为"装错骨架"（把 2C 卖货后台当内部中台），已由功能开关门控隐藏但未物理清理，冻结待专项盘点 |

一句话概括差距：**K3 解决了"好不好看、动不动、说不说中文"，控制台 v2 解决了"菜单按业务组织"，两者合起来才是北极星要的中台。**

## 3. 排版规范对齐

### 3.1 颜色：亮/暗 token ↔ 深色青绿方向

北极星方向是"**深色青绿 + 中文文案**"。对齐方式很直接：

| 角色 | K3 现状 | 主项目方向 | 统一结论 |
|---|---|---|---|
| 品牌强调色 | `--ui-accent`：亮色 teal-600（`13 148 136`），暗色 teal-300（`45 212 191`）；Tailwind `primary` 色板即 teal 家族（`#14b8a6` 系） | 无界青绿（teal）为唯一品牌强调色 | ✅ **天然一致，无需改**。青绿就是 teal，一套色板两边通用 |
| 暗色主题 | 近黑中性画布（`9 12 17`）+ 深灰蓝表面（`17 24 39` / `24 33 47`）+ 青绿强调 | "深色青绿"基调 | **兼容，可直接作为深色青绿的工程实现**：深色中性底 + 青绿点缀。若老板希望"青绿感更强"，只需微调暗色表面色相（往青灰方向偏几度），不动结构——见开放决策 D2 |
| 亮色主题 | slate-50 画布 + 白表面 | 主项目以深色为主基调，亮色为可选 | 保留双主题同源变量，默认主题待拍板（开放决策 D2） |
| 状态色 | 失败红 / 警告黄 / 成功绿，只表达真实状态 | 一致（异常必须主动上浮到总览） | ✅ 一致，状态色不作装饰 |

原则：**只维护一套 `--ui-*` 变量，亮暗同源**。禁止出现"主项目一套变量、K3 一套变量"的双轨撕裂（见 §7 风险 R1）。

### 3.2 宽度、栅格与断点

| 规范项 | 主规划参考值 | K3 现状 | 取舍建议 |
|---|---|---|---|
| 主内容最大宽度 | 规划文档容器 1180px | `max-w-7xl`（1280px），表格页可 `fullWidth` 放宽 | **不硬改成 1180**。中台是数据密集型应用：概览/阅读型页面对齐 ~1180px（结论先行、行长舒适）；表格/账单/任务记录等密集页面保留 1280px 或全宽，避免列被挤压换行。1180 作为"阅读宽度"而非"全局容器" |
| 栅格 | 规划文档 grid2/grid3 卡片栅格 | K3 卡片栅格按 Tailwind `md/lg` 断点 | 卡片栅格在 **≤860px 一律单列堆叠**（对齐主规划 860 断点的移动优先语义） |
| 断点 | 860px（移动切换） | Tailwind 标准：`md` 768 / `lg` 1024（侧栏在 lg 切换抽屉） | **壳层不动**（侧栏 1024 切换是 App 级行为，已有测试覆盖）；**内容层**把 860 作为"卡片堆叠 / 指标换行"的对齐参考。不往 tailwind.config 里塞自定义 860 断点，避免与既有 `md/lg` 用法混滑 |
| 徽章（badge） | 规划文档用状态徽章：内部可用 / 待复核 / 已冻结 / 可演示 | K3 用语义色徽章表达任务/账号真实状态 | 应用内徽章**只表达业务真实状态**（succeeded/failed/active/disabled 等），不引入文档级成熟度徽章；语义色规则两边一致 |
| 侧栏宽度 | — | 256px 展开 / 72px 折叠 | 保持。与菜单换骨（§5 阶段 C）无关，换骨只改分组与命名，不改宽度 |

## 5. 分阶段融入路线

### 阶段 A：中文化 + 动效 + 黄金路径（✅ 本轮已完成）

- 内容：界面全中文说人话；SVG 空状态插画、骨架屏扫光、任务进度环；视频黄金路径 outcome-first。
- 验收标准：四条门禁绿（eslint / vue-tsc / vitest 152 文件 964 用例 / build）；`prefers-reduced-motion` 降级可用；审查包截图齐全。
- 停止点：状态保持"可演示/待复核"，不上调。

### 阶段 B：全站 token 统一 + 菜单改名（清单级工作量）

- 内容：
  1. 把 `--ui-*` / `.ui-panel` 语义类推广到剩余高频页面（用户、分组、账号、用量、对账、设置），**每次一个页面切片**，复用阶段 A 模板，不为每页发明新样式；
  2. 按 §4 表逐条改菜单文案（i18n 双语 key 对称更新）；
  3. 同步更新断言了菜单文案的测试（`AppSidebar.spec.ts`、`navigation.spec.ts` 等）。
- 工作量特征：**清单级**——每个页面切片 ≈ 半天到一天（改样式类名 + 跑门禁 + 截图），菜单改名 ≈ 一天（文案 + 测试断言 + 引导流程核对）。
- 验收标准：每个切片四门禁绿；`git diff` 中无路由/守卫/开关改动；双语 key 对称；明暗双主题 + 1440/390 双视口截图无断层。
- 停止点：任何切片出现业务逻辑漂移或关键测试失败，立即停在该切片，`git revert` 该切片，不扩散。

### 阶段 C：IA 换骨——控制台 v2 六导航

- 内容：菜单结构从"技术后台"换成六导航（总览 / 密钥库 / 成员与开卡 / 任务记录 / 系统折叠 + 2C 遗留冻结隐藏）。
- **与 wujie 分支的关系与取舍**：wujie 分支（`wujie/video-capture-moat-20260702`）**已实现**控制台 v2 的核心页面——`BossOverviewView`（老板总览：动画数字卡、趋势、模型分布、成员排行、异常红条）、`KeyVaultView`（密钥库双标签）、`StaffView`（成员与开卡）、`AiRecordsView`（AI 调用记录）、`AnimatedNumber.vue`，以及 demo 模式 5 顶栏 + 系统折叠组的壳层。K3 实验的价值在**视觉 token 层、壳层质感、动效与中文化**，不在重造这些业务页面。
- 取舍建议：**不重复造轮子**。阶段 C 以 wujie 的控制台 v2 页面为业务骨架，把 K3 的 `--ui-*` token 层与壳层质感"穿"到这些页面上；K3 分支上已打磨的视频黄金路径页面（总览/创建/任务记录）作为任务记录导航下的主力视图保留。
- 验收标准：六导航对三类角色各看各的；异常能上浮到总览；2C 遗留菜单不可见但路由与开关未删；四门禁 + 导航/守卫/feature-access 测试全绿；老板 3 秒能扫出成本与异常。
- 停止点：合并策略未经拍板（开放决策 D4）前不动手；换骨期间任何权限入口被隐藏即停。

### 阶段 D：与 QCanvas 的契约对齐验收

- 内容：按 `docs/api/video-gateway-contract.md`（v3 真相源）逐项核对中台侧表现：content[] 多模态、usage/尾帧、轮询、扣费与账本口径（`unified_total_actual_cost`、currency/pricing_source）、`production_authorized` 逐 Key 放行的前端呈现。
- 验收标准：契约核对清单全过；真实付费链路复核按 R2-A 模式走人工 gate（需老板逐 Key 授权，前端只呈现不触发）。
- 停止点：**不主动触发真实 Provider**；契约缺口只记录为提案，不在本路线内自行实现。

## 6. 开放决策清单（需要用户拍板）

| # | 决策点 | 选项 | 建议倾向 |

## 7. 风险与回滚

| # | 风险 | 影响面 | 缓解 | 回滚单元 |
|---|---|---|---|---|
| R1 | **双轨 token 撕裂**：`--ui-*` 新语义类与旧 `gray-*/dark-*` 直写类长期共存，页面一半新一半旧，视觉漂移 | 全站观感不一致，后续维护成本翻倍 | 阶段 B 严格"一次一个切片"，每切片四门禁 + 截图；保留 token 契约测试（`visualTokens.spec.ts`）兜底；不新增第二套变量 | 按切片 commit `git revert`；最坏情况整段回退 `style.css` + `tailwind.config.js` + 契约测试 |
| R2 | **菜单改名波及既有测试**：`AppSidebar.spec.ts`（导航构建器断言）、`navigation.spec.ts`、新手引导（onboarding）步骤、E2E 选择器 | 改名不当会导致测试红、引导流程卡死 | 只改 i18n 文案与 label，**路径不动**（引导选择器全部绑路径：`#sidebar-channel-manage`、`#sidebar-group-manage`、`#sidebar-wallet`、`[data-tour="sidebar-my-keys"]`）；改名 PR 必跑全量 vitest；隐藏 2C 菜单前确认引导步骤降级 | 文案与测试断言同一 commit，单独 revert 即可 |
| R3 | **IA 换骨期权限入口被隐藏**：六导航重排时误伤角色可见性或 feature flag | 员工/管理者找不到入口，或看到不该看的 | 换骨 diff 中禁止触碰 `applyFeatureFlags`、`finalizeNav`、路由守卫；`guards.spec.ts`、`feature-access.spec.ts`、`video-route-access.spec.ts` 全绿才可合入 | 换骨为独立阶段独立 commit 段，整段 revert |
| R4 | **分支合并冲突**（D4）：两分支都改了壳层与菜单 | 合并期长、易引入回归 | 合并前冻结两侧壳层改动；合并后重跑全量门禁 + 截图矩阵 | 合并前打 tag/记录 HEAD，合并失败直接回到合并前 HEAD |
| R5 | **深色默认切换**（D2）暴露暗色覆盖不全 | 部分页面暗色下对比度/层级未验证 | 切默认前补齐暗色截图矩阵（管理员视频总览、创建页、对账页）与可访问性走查 | 默认值一行配置，秒级 revert |
