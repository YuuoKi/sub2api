截图问题与根因

  • 分组名称全局唯一，但旧页面只加载活跃且当前平台可见的分组；同名分组被隐藏时仍会占名，导致“无可用分组”与 group name already exists 同时出现。
  • 图片账号只按平台过滤，没有按价格、模型和图片能力过滤，因此可能把视频组放进图片账号。
  • 图片账号目录错误混入 3 个文字模型，页面信息与“HC-ATOM（图片）”语义不一致。
  • 创建账号没有稳定的 Idempotency-Key，账号创建与分组绑定也不是原子操作。
  • 员工 media/video 双 Key 只检查组 ID，没有证明两组能力不同，存在错误绑定风险。

改动清单与安全边界

  • 图片弹窗只显示 5 个授权图片模型；文字、视频和 Dola 不进入图片账号目录。
  • 图片组必须是活跃 HC 组、允许图片与批量图片、配置 1K/2K/4K 正价格、包含精确 5 个图片模型且不包含视频模型。
  • 视频组必须是活跃 HC 组、配置 480p/720p/1080p 正价格、包含当前通道对应的 V1 或 V3 视频模型且不包含任何图片模型。
  • 快速建组会复用同名且能力正确的现有组；名称冲突、停用组或能力不匹配均给出中文原因。相同活跃 toast 在短时间内只显示一次。
  • 分组加载失败不会伪装成“当前没有分组”，账号与视频通道保存前会再次验证所选组。
  • HC 图片账号在 API 层也禁止无分组创建或显式清空分组；真实数据库故障不会被误报成“分组不存在”。
  • 密钥库与通用开户弹窗都按一次打开会话复用稳定 Idempotency-Key；批量开户的每个逻辑账号使用独立 Key。
  • 后端在事务内完成账号和分组绑定，失败时不留下无组账号或调度缓存残影；真实 PostgreSQL 回滚测试覆盖创建和更新两条路径。
  • 员工双 Key 后端强制 media/video 两组能力互斥；错误平台、停用组、缺价或模型不完整均拒绝开卡。
  • HC 组图片价格可直接满足异步图片模型可见性判断，不再要求额外全局价格。
  • 同步模型自动规范化 prompt / count / quality / reference_images；Seedream 只接受文生图，Doubao 支持参考图。
  • 异步模型使用平铺请求体，支持 1K/2K/4K、比例、参考图；GPT 两个模型会把档位换算为真实上游像素，且 4K 严格低于上游像素上限。
  • GPT 两个模型使用 x-api-key，Gemini 使用 Bearer；支持 queued/running/success/failed/cancelled 与结果 URL。
  • 安全的 failReason 可回传，当前解密 Key、疑似密钥或签名 URL 会被脱敏；无静默官方回退。
  • 单任务、单输出、模型、比例或协议不完整时，在账号选择、解密、计费和网络请求前失败。
