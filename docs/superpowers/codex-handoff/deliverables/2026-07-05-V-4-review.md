## 1. 目标

- 后端 `/admin/dashboard/stats` 增加视频花费汇总，按 V-3 `usd_cny_rate` 折算成 USD。
- 增加视频花费分 provider 明细。
- `users-ranking` 保持原有 LLM `actual_cost` 排名和字段语义，同时给每个 ranking item 增加 `video_cost`。
- 增加合计字段，方便前端或 Claude 区分 LLM、视频、统一总花费。
- 不修改 `frontend/**`，不真实调用 provider，不读取 `.env` / key / token / cookie。

## 2. 实现选择

本轮选择低侵入方案：扩展现有 `/admin/dashboard/stats` 与 `/admin/dashboard/users-ranking`，不新增新端点。

- `/admin/dashboard/stats` 新增：
  - `video_total_cost`
  - `today_video_cost`
  - `unified_total_actual_cost`
  - `unified_today_actual_cost`
  - `cost_currency`
  - `video_spend_by_provider`
- `/admin/dashboard/users-ranking` 新增：
  - ranking item: `video_cost`
  - response total: `total_video_cost`
  - response total: `total_combined_actual_cost`

现有字段 `total_actual_cost`、`actual_cost`、`total_requests`、`total_tokens` 均保持原有 LLM usage 口径，不把视频混进去，避免破坏既有前端和报表。

## 5. 验收点

- `/admin/dashboard/stats` 可返回视频费用：
  - `video_total_cost`：视频总费用，折算 USD。
  - `today_video_cost`：今日视频费用，折算 USD。
  - `unified_total_actual_cost = total_actual_cost + video_total_cost`。
  - `unified_today_actual_cost = today_actual_cost + today_video_cost`。
  - `video_spend_by_provider`：按 provider 分组的 USD 折算费用与条数。
- `/admin/dashboard/users-ranking` 保持旧排名逻辑：
  - `actual_cost` 仍是 LLM usage 实际扣除。
  - `video_cost` 是同一时间范围内该用户的视频费用，折算 USD。
  - `total_combined_actual_cost = total_actual_cost + total_video_cost`。
- 真实 integration 已验证：`14.4 CNY / 7.20 = 2.0 USD`，再与 LLM `3.0 USD` 合并为 `5.0 USD`。

## 7. 风险

- `video_spend_by_provider` 以 `video_usage_logs.provider` 分组，不是 API channel 维度；视频网关当前没有 channel_id 字段。
- `users-ranking` 只给现有 LLM ranking rows 增加 `video_cost`，不改变原来的 LLM 排序和入榜逻辑；只有视频、没有 LLM usage 的用户不会出现在 ranking rows，但其费用会计入 `total_video_cost`。
- `settings.usd_cny_rate` 若被设置成无效字符串，SQL 会回落 `7.20`，不会自动拉汇率。
- 没有真实 provider 调用；费用数据来自本地表与 mock/integration 插入。
